# myRAG · 讨论结论与产品定位（备忘）

> 来源：Arthur ↔ 老王同志 产品讨论（2026-09-11）  
> 配套长文：`docs/白话说明-应用场景与实现.md`  
> 性质：产品定位 / 需求分析备忘，非正式法务或技术终稿

---

## 1. 核心结论（先看这四句）

1. **Agent-T 现在不依赖独立 RAG 也能成立**——单份合同 + 规则清单 + LLM（评分/补盲/追问）足够撑起 MVP。  
2. **中长期若要对标模板对照、法规引用、多合同项目，值得有独立的检索底座（myRAG）**。  
3. **关系定位**：Agent-T = 审查编排与结论产品；myRAG = 可选的知识与检索服务（插件，不是心脏）。  
4. **铁律不变**：清单规则决定 `通过/需关注/N/A/未找到`；RAG/LLM 只提供带出处的参考，不覆盖规则门禁（与 Agent-T Design B 一致）。

类比：Agent-T 是体检报告；myRAG 是化验设备。基础问诊可以不做化验；深度体检再接。

---

## 2. 和 Agent-T 现状的对照（只读观察）

截至 2026-09-11 对 `ARTHUR-BBU/Agent-T` 的观察：

- **没有**独立 RAG / 向量库 / Dify / RAGFlow 集成  
- 最接近「检索」的是 `clause_index`：给**当前这一份合同**切条款编号，便于定位——是「这篇作文的目录」，不是「图书馆」  
- Claude Code 团队近期工作重心在外部体检与工程硬化（证据链、限流、TTL 等），成长日记下一站写的是阶段 2「质量层」，**待办清单未挂「接 RAG」**

因此：myRAG 是**新开的底座线**，不是从 Agent-T 里拆出来的现成服务。

---

## 3. 什么时候要 / 不要 myRAG

| 场景 | 要不要独立 RAG | 说明 |
|---|---|---|
| 单份上传 + 清单审查 + 追问解释 | 否 | 文档内上下文 + 条款索引即可 |
| 公司标准模板对照 / 红线库 | 要（可先薄） | 开卷对标准答 |
| 法规 / 内控制度引用且可点回原文 | 要 + 强出处 | 证据链 |
| 多合同项目 / 历史案例检索 | 要 | 项目级 scope |
| 纯制度知识问答 / 对外只暴露审查 API | 要（可作底座） | 用户无感或单独小入口 |

## 4. 产品边界（需求分析用）

### Agent-T 负责

- 上传、品类/立场、清单门禁、证据链、报告、Copilot 解释与改写  
- 用户感知：「帮我审这份合同」  
- 指标：准、可对质、不乱盖「没问题」章  

### myRAG 负责

- 模板库、法规/制度库、项目文档库  
- 对外薄能力：`retrieve(query, scope) → passages + citations`  
- 可选：独立「知识问答」入口；资料上传/下架/权限（法务可自助更新）  
- 指标：找得准、引得出处、换实现不改审查主流程  

### 明确不做

- 不用向量库冒充审查正确性  
- 不用 RAG 替代金标 / 红线 / 清单  
- 密钥与未脱敏真实合同不进共享库  
- 不为技术选型先造大平台——场景验证优先

## 5. 实现与开发方式（共识）

流水线五步（人话）：

> 资料进馆 → 按条款切碎 → 做成可搜索卡片 → 按问题找出相关卡片 → 塞给模型并强制带出处  

三条开发路：

1. **开箱产品验证**：Dify（产品壳/编排快）或 RAGFlow（难文档解析与引用强）  
2. **确定嵌 Agent-T 后再写胶水**：LangChain / LlamaIndex 等，控切块与审查衔接  
3. **更早的薄知识层**：模板 + 关键词 / 条款级挂载，不一定一上来就上向量  

演进顺序（建议）：

```text
现在   ：Agent-T 单文档做透，不强制挂 myRAG
近未来 ：Docker 起 Dify 或 RAGFlow，只验「标准模板库」是否有人用
验证后 ：retrieve() 接到 Agent-T「模板对照 / 参考依据」
再往后 ：多文档项目、法规库、权限与更新流程
```

许可备忘（选型时核对，非法务终审）：

- Dify：开源可用；多租户 SaaS 等有附加条款，上线前确认  
- RAGFlow：Apache-2.0，相对清爽

## 6. 需求优先级草案

| 优先级 | 需求 | 验收（白话） |
|---|---|---|
| P0 | Agent-T 不依赖 myRAG | 关掉检索服务，单文档演示仍完整 |
| P1 | 模板库检索 + 出处 | 能指出与标准模板差异所在条款 |
| P1 | 检索不得覆盖规则结论 | 规则结果不被 RAG 擅自改写；候选补盲可关 |
| P2 | 法规/制度引用可点开原文 | 每条参考有 locator |
| P2 | 项目多文档 scope 检索 | 只在指定项目内搜 |
| P3 | 独立知识问答入口 | 不审合同也能问制度 |
| P3 | 资料管理后台 | 法务自助上下架，不找开发 |
